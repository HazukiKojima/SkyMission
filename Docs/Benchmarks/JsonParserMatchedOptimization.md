# 3ライブラリへ同じ最適化を適用した比較

2026-11-09。REDoxだけに型付きキャッシュを追加した前回の比較を補うため、
System.Text.Jsonとnlohmann/jsonにも同じ一括取得・検証・キャッシュ方式を実装した。
変更対象は比較用コード。ゲーム本体のパーサー選択やRE:DOX本体は変更していない。

## そろえた条件

- 全てUTF-8から解析し、呼び出し元の入力バッファが解放されても文書を使用できる。
- 同じAI設定30項目を一度のプロパティ列挙で読み、項目名→出力位置のハッシュ表で配置する。
- 全項目の存在、数値型、floatの有限性を検証する。未知の項目は無視し、失敗時は出力を変更しない。
- 初回取得で文書単位の型付きfloat配列を保存する。再取得は辞書でキャッシュを探し、30値を出力へコピーする。
- 一括取得・キャッシュ取得は全て同じ順番の30値を消費し、チェックサムを比較する。
- 個別取得ケースでは3者とも型付き配列キャッシュを使わず、DOMから検索・float変換・有限性検証を行う。

REDoxとSystem.Text.Jsonは**同じC#ソース**を条件コンパイルし、型と解析APIだけを差し替えた。
nlohmannは同じ処理をC++で実装した。キャッシュコピーをコンパイラーに省略させないため、
一括取得を非インライン関数にして出力バッファへ書き込む。

比較対象の入力は重複キーを含まない。不正型・欠落・float範囲外・非オブジェクト・未知の項目を含む
追加ケースでも、3者の結果、出力不変、キャッシュ再取得、入力バッファの所有権を確認した。
重複キーの扱いやJSON編集・DTOデシリアライズの性能は今回の比較対象外。

## 結果

C++ Release /O2、3プロセス×7標本＝各21標本の中央値。**µs/操作、低いほど速い**。

| 処理 | REDox 同条件最適化 | System.Text.Json 同条件最適化 | nlohmann/json 同条件最適化 |
| --- | ---: | ---: | ---: |
| AI設定の解析・破棄 | **0.756** | 1.791 | 9.201 |
| 実設定24文書の解析・破棄 | **11.498** | 25.577 | 123.997 |
| AI設定の解析＋30項目初回取得 | **2.664** | 4.265 | 10.321 |
| 取得済み30値のコピー | 0.049 | 0.049 | **0.030** |
| DOMから30項目を個別検索・変換 | 6.765 | 3.019 | **1.144** |

同じ方式でも、今回の初回一括読み込みはREDoxがSTJの約1.60倍、nlohmannの約3.87倍の速度だった。
一方、キャッシュ再取得のREDox/STJ差はほぼなくなった。
以前の「REDoxだけ再取得が大幅に速い」という差は、キャッシュの有無によるもので、ライブラリ固有の優位とはいえない。

取得済み30値のコピーには、3者ともJSONパーサーの検索処理はない。
この行の差をパーサー本体の性能差と解釈しない。
DOMの個別検索では、引き続きnlohmannが速かった。

| 解析するデータ | REDox | STJ | nlohmann |
| --- | ---: | ---: | ---: |
| 数値10,000要素 | 118.824 | 347.185 | 1397.722 |
| 数値100,000要素 | 1233.930 | 2964.709 | 15933.817 |
| 機体1,000件・日本語・入れ子 | 167.536 | 496.108 | 2591.914 |

大きな配列の行はDOM構築・破棄のみで、全数値のfloat変換までの時間ではない。

## 残る条件差と限界

これはC++ゲームからの実用的な呼び出し経路の比較で、完全に同じ機械語処理の比較ではない。
REDox/STJはNative AOT DLLのハンドル管理・ロック・ネイティブ境界を通り、nlohmannはC++から直接呼ぶ。
nlohmannには同じハンドル表や.NETのロックを人工的に追加していない。
キャッシュ後の数十ns規模の差には、この経路の差も含まれる。
純粋なパーサー内部だけの順位や、マルチスレッドの競合性能を示すものではない。

DOM内部表現、プロパティ列挙順、数値の内部表現、メモリ管理も各ライブラリのまま。
今回そろえたのは入力・必要な結果・検証・取得アルゴリズム・キャッシュ条件である。
全データ・全用途での優劣、ピークメモリ、ゲーム全体の起動時間やFPSは断定しない。

環境はRyzen 5 5600X、MSVC 19.51、.NET Native AOT 10.0.14、REDox 1.0.3、nlohmann/json 3.12.0。
ウォームアップ後、約100msの標本を測り、実行順を巡回させた。計測同士は並行実行していない。
ディスクI/O・DLLロードは含めない。.NETの標本前GCは測定外、標本中のGCは含む。
