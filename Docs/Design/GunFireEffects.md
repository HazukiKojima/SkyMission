# 機関砲の発射エフェクト

## 表示内容

4門すべてにマズルフラッシュと薄い発射煙を出し、各銃口で2発に1発を曳光弾として表示する。
L1・R2とL2・R1で交互に光らせ、4門すべてが同時に非表示になる周期を避ける。
弾モデル、発射間隔、射撃補正、速度、寿命、ダメージ、命中判定、音声は変更しない。

| 演出 | 初期値 |
| --- | --- |
| 閃光 | 寿命0.065秒、半径2.5、火炎長8 |
| 曳光弾 | 直近0.018秒の移動距離、最大長120、外周4px・芯1.5px |
| 発射煙 | 寿命0.35秒、半径0.8→2.8、不透明度は最大0.16 |
| 煙の移動 | 自機速度を25％継承、減衰率2、上昇速度3 |
| 件数上限 | 閃光4、煙64、曳光弾256区間/フレーム |

時間は秒、距離はワールド単位、線幅は1920×1080基準。
値は`GunEffectSettings`にまとめる。色は白黄色の芯と橙色の外周、煙は灰色とする。
新しい画像アセット、画面全体の発光、揺れ、残像は追加しない。

## データの流れ

1. `ProjectileSystem::FireVolley`が発射を受け付け、各銃口の`GunShotEvent`を生成する。
2. 通知には銃口番号、実際の発射位置、発射方向、自機速度、フレーム内の経過時間、発射順を格納する。
3. `FlightScene`が`TakeShotEvents()`で通知を受け取り、`CombatEffectSystem`へ渡す。
4. 演出システムが閃光と煙の寿命・上限を管理し、`CombatEffectSnapshot`へ格納する。
5. `GunEffectPresenter`が既存の投影・発光・手続き的な煙の描画を使い、HUDより先に表示する。

存在数上限などで発射に失敗した場合は、通知も曳光弾の順番も進めない。
発射後すぐに敵や海面へ接触した場合も通知を残し、閃光と煙を生成する。
通知と曳光弾の区間は取り出すと消費され、次の有効フレームの更新時にもクリアされる。
再設定時は発射順と未消費の演出情報をリセットする。

## 寿命と追従

閃光は銃口番号ごとに最新の発射へ更新する。現在の機体行列で銃口位置を求め、姿勢と移動に追従させる。
低FPSで寿命をまたいだ通知は表示上の年齢を寿命の半分までに抑え、一度は表示する。実弾の時刻は変更しない。
自機削除時は閃光だけを消し、すでに放出された煙と弾は独立して更新する。

煙は発射ごとに1粒生成し、初期年齢にフレーム内の経過時間を反映する。
初期位置と速度を保持し、減衰速度の積分値`(1 - exp(-drag * age)) / drag`で位置を求める。
位置を描画フレームごとに加算しないため、同じ経過時間なら同じ場所に描画される。
上限到達時は古い煙から置き換える。

曳光弾は実弾の現在位置・速度・発射位置から区間を求め、発射位置より後ろへ伸ばさない。
命中時は最初の接触点、海面と寿命切れでは実際に移動した終端を使う。
消滅したフレームの区間は表示するが、その次のフレームへ残さない。

## 投影と描画予算

曳光弾専用の区間投影では、透視除算の前にクリップ空間の6面と正のwで線分を切る。
片端が画面外やカメラ後方でも、画面内に存在する部分は描く。既存の点投影と破片の投影は変更しない。
不正値、完全に画面外の区間、完全に背面の区間は描かない。

描画順は発射煙 → 爆発・ロケット → 曳光弾・閃光 → 着弾 → HUD。
HUD用の6000頂点を維持し、閃光と曳光弾の必要量を最大4000頂点まで先に予約する。
通常の演出は予約分を使わず、発射演出を描く直前に予約を解除する。
各描画前に残り予算を確認し、頂点上限で例外が発生しないよう省略する。
ほかの演出の予算を保守的に見積もり、不足する場面では薄い発射煙を先に省略する。

**既存の爆発・煙と同様、3D物体による遮蔽は行わない。**
曳光弾は接触点で止まるが、手前の機体などによる表示上の遮蔽とは別の制約である。

## 検証

- 発射通知の消費、4門の位置、自機速度、フレーム内年齢を確認する。
- 曳光弾の交互表示、発射失敗時の順番、再設定時のリセットを確認する。
- 命中・海面・寿命の終端と、消滅した次のフレームでの区間消去を確認する。
- 30/60/144FPS・0.25秒更新で発射煙の密度と低FPS時の閃光を確認する。
- 銃口追従と煙の独立、自機消失、各件数上限を確認する。
- 画面端・近クリップ面・カメラ後方・不正値の区間投影を確認する。
- 全演出の最大件数を同時に描き、HUDの予約領域を維持できることを確認する。
- 800×600と1920×1080のGPU読み戻し画像に発射演出を含め、外観を確認する。
- Debug/Release x64ビルド、既存を含む回帰テスト、全HLSLの両最適化設定での警告なしコンパイルを実行する。

### 確認結果

2026-10-31、Debug/Release x64のソリューションビルドと回帰テストが成功した。
全HLSLを`/Od /WX`・`/O3 /WX`でコンパイルし、警告がないことを確認した。
最大件数時のHUD予約と発射煙の優先省略、実アセットの銃口位置との一致も検証した。
800×600・1920×1080のGPU読み戻し画像で、発射演出と照準・文字の表示を確認した。
書式のdry-run、プロジェクトとフィルターのXML検証も成功した。
