# コードの可読性統一とHLSL警告確認

## 目的と対象

処理の目的・順序・責務を追いやすくし、ゲームの動作・描画・音・設定の互換性を維持する。
EngineとGameの自作C++・HLSL、およびTestsのC++を対象とする。
外部ライブラリ、自動生成コード、ビルド成果物は整形しない。

## コード規約

| 対象 | 基本規則 |
| --- | --- |
| クラス・構造体・関数 | PascalCase |
| 引数・ローカル変数 | camelCase |
| メンバー変数 | m_camelCase |
| 新しく導入する定数 | kPascalCase |
| 単位が曖昧な変数 | Seconds・Radians・Pixelsなどを名前へ含める |

公開済みの定数名、JSONキー、シェーダーセマンティクス、定数バッファーとNative AOTのデータ配置は維持する。
数式の係数やN・V・UVなどの一般的な表記は、その意味が明確なら維持する。

- C++はタブ幅4、開始波括弧は同じ行、原則110桁以内とする。
- HLSLはスペース4文字、開始波括弧は次の行とする。
- 一行に複数の処理を書かず、複数変数の宣言は分ける。
- 初期化・判定・更新・後始末は、意味のまとまりで空行を入れる。
- 複雑な計算には意味が分かる中間変数を置き、単純な式の過剰な関数化は避ける。
- 説明は日本語の`//`コメントとし、目的・理由・制約を書く。
- 代入内容を言い換えるだけのコメントや、不要なコメントアウト済みコードは残さない。
- コメントの文末には「。」を付けない。正式名称やライセンス表記は維持する。
- `// namespace`はツールが生成する構造上の目印として維持する。

リポジトリ直下とシェーダーフォルダーの`.clang-format`に、各言語の書式を記録する。
clang-format 19.1.5で適用・確認している。

```powershell
$cppFiles = Get-ChildItem Engine,Game,Tests -Recurse -File |
    Where-Object Extension -in '.cpp','.h' | ForEach-Object FullName
clang-format -i @cppFiles

$shaderFiles = Get-ChildItem Engine/Renderer/Shader -File |
    Where-Object Extension -in '.hlsl','.hlsli' | ForEach-Object FullName
clang-format -i @shaderFiles
```

整形後は必ず差分を確認する。命名とコメントの整理を整形ツール任せにしない。

## CombatAudioの責務と寿命

ヘッダーは宣言と所有するデータを示し、初期化・音声合成・再生・終了処理は`.cpp`へ分離する。
公開関数とコピー禁止の制約は維持する。

- 射撃音と命中音は内部列挙型`SoundKind`で区別する。
- サンプルレート・音声数・音量・再生時間は名前付き定数で管理する。
- 合成式、乱数シード、音量、同時再生数、同一フレーム内で音をまとめる動作は維持する。
- 初期化に失敗した場合は作成済みリソースを解放し、ゲームは無音で継続する。
- 再初期化時は、前回の音声とエンジンを解放してから作成する。
- XAudio2はサンプルを参照するため、サンプルを所有する配列より先に音声を破棄する。
- ソース音声 → マスタリング音声 → エンジン → 所有するCOM初期化の順に終了する。
- `CoInitializeEx`が成功した分だけ`CoUninitialize`する。別方式で初期化済みの場合は呼び出し元のCOMを解除しない。

PImplや汎用音声基盤は追加しない。音声専用のライブラリ指定は実装ファイルに置く。

## HLSL X4000の調査結果

FXCの最適化なし(`/Od`)と最適化あり(`/O3`)で確認した。

| 対象関数 | 修正前の警告 | 経路の確認結果と変更 |
| --- | --- | --- |
| CalculateSunSpecular | /Od | 背面はゼロ、それ以外は反射値を返していた。結果をゼロで初期化し、有効な面の反射値を代入して返す |
| OceanHorizonFog | /Od | RayBoxのout引数は全経路で代入され、交差なし・空区間はゼロを返していた。有効区間の積分と戻り値を明示する |
| SampleSceneSkyAbove | /Od・/O3 | 最初の有効な空の色、または代替色を返していた。代替色を初期値にし、最初の探索成功だけを保持する |
| FilmDust | /Od | しきい値未満はゼロ、それ以外は埃の濃さを返していた。結果変数へ条件付きで代入する |
| FilmScratch | /Od | しきい値未満はゼロ、それ以外は傷の濃さを返していた。結果変数へ条件付きで代入する |

警告が示した関数に、実際の未代入経路は見つからなかった。
早期returnと展開ループ内のreturnを避けた等価な構造で警告が消えることから、今回のX4000はFXCの制御フロー解析による誤検出と判断した。
コンパイラー内部の原因そのものを特定したわけではない。

警告の無効化は行わない。結果の初期値は元の早期return値または代替色に対応させる。
空の探索回数8回、霧の積分回数24回、数式、描画パラメーターとバッファー配置は維持する。
フィルム処理のローカル変数名も変更し、定数バッファーの`dust`・`scratch`との同名を避ける。

プロジェクトのHLSLコンパイルに`/WX`を追加する。
回帰テストでは全シェーダーを`/Od /WX`と`/O3 /WX`の両方でコンパイルする。
描画テストが参照する通常名のCSOには`/Od`の成果物を使う。

## 検証

- Debug・Releaseのx64ビルドと既存回帰テストを実行する。
- 全シェーダーを両方の最適化設定でコンパイルし、警告も失敗として検出する。
- 音声の初期化前更新、連続再生要求、再初期化、破棄をテストする。
- COMを明示的に初期化していない別スレッドとSTA初期化済みの別スレッドで、呼び出し元のCOM所有権が保たれることを検証する。暗黙のMTA参加も含め、呼び出し前後の状態を比較する。
- マウス以外のデバイス削除でも、蓄積したマウス移動量が維持されることを検証する。
- 既存のGPU読み戻しテストで、800×600と1920×1080のHUD・演出を確認する。
- 修正前後の照明・海面・海面霧・フィルムシェーダーを同じ入力で描画し、両解像度と両最適化設定で画素差を比較する。

音声ライフサイクルのテストは、音声デバイスがない環境でも失敗しないことを確認するもので、聴感の自動判定は行わない。
画素比較は固定入力での等価性を検証するもので、全カメラ位置・全アセットの外観を保証するものではない。

### 固定入力での画素比較結果

修正前のコミット`7f7c4b1`と作業中のHLSLをD3D11の検証用描画で比較した。
対象はBasicPS・OceanPS・OceanFogPS・RetroFilmPS。各3条件、2解像度、2最適化設定の計48比較で、RGBA8の画素差はすべて0だった。
条件には照明の向き、空の探索成功・代替色、霧の空区間、埃と傷の出現・非出現を含む。
検証用プログラムと比較ログは一時ディレクトリへ生成し、製品や回帰テストの依存には追加していない。

### 最終確認結果

2026-10-31、VS2026・v145・.NET 10の環境で以下を確認した。

| 確認項目 | 結果 |
| --- | --- |
| ソリューションのDebug / Release x64ビルド | 成功 |
| 既存テストと音声・デバイス削除の回帰テスト | 全件成功 |
| 全HLSLの /Od /WX・/O3 /WXコンパイル | 警告・エラーなし |
| clang-format 19.1.5のdry-run | 全対象で成功 |
| プロジェクト・フィルターのXML | 正常 |
| 固定入力のシェーダー画素比較 | 48件すべて差分0 |

音の聴感確認は未実施。合成式・音量・サンプル数を維持し、再生要求とライフサイクルを自動検証した。
