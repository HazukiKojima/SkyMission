# 高高度の薄雲の試作と積雲描画

現在の初期設定は、少量の厚い積雲と、より高い場所の薄い筋雲を併用する。
`Assets/Environment/Clouds.json`は`coverage: 0.18`、`density: 0.0015`。
厚い積雲だけ雲量係数を一時的に1/12倍（1/4にした後、さらに1/3）とし、生成判定に使うcoverageを0.015へ抑えている。筋雲のcoverageは0.18を維持する。これは雲量パラメーターの比であり、視点ごとの画面被覆が厳密に1/4になる指定ではない。
厚い雲の生成範囲を2,500m上へ移し、設定上の下端を4,300m、上端を13,000mとした。密度場の発達範囲と雲量は維持し、筋雲の標準高度14〜16kmも維持する。
`density: 0`では筋雲のみ、`enabled: 0`ではすべての雲を無効にする。
JSONの項目と定数バッファの配置は維持し、密度の有効範囲に0を追加した。負値・NaNなどの拒否は維持する。

## 高高度の薄雲

- `CirrusClouds.hlsli`で、`max(14,000m, top + 1,000m)`とその2,000m上（標準設定では14,000m・16,000m）に薄い雲域を生成する。
- 2つの雲域はワールドに固定し、風で移動する。カメラを動かすと視差が出る。雲の中心や個別オブジェクトの配置は使わない。
- 長い筋、細い繊維、大きな晴れ間を連続した2Dノイズと領域の歪みで作る。半透明のため、雲の中にも青空が透ける。
- 最終合成のフル解像度で直接評価する。低解像度の雲ターゲットを拡大せず、レイマーチや画素ごとのディザも使わない。
- 地平線近くで投影が拡大することを考慮し、ワールド上の交点の画素微分から模様の細かさを減らす。単純な距離×画角だけでフィルタを決めない。
- 深度から機体・艦船・海面より奥の薄雲を遮蔽する。下から見たときは、手前の積雲の透過率でも薄雲を減衰させる。
- 上から見る場合と下から見る場合で雲域の合成順を変える。100〜180kmで遠景へ消し込む。
- 合成は既存のフィルム色調・粒子の前に行う。雲も元のシーンと同じ色調処理を通し、背景の空の色や太陽、HDRスカイの描画は変更しない。

## 色と粗さの修正

- 青空への置き換え処理（`CleanSky`）は撤去した。空のHDRテクスチャ・大気色・太陽・既存のフィルム設定をそのまま使い、空の色を変えずに雲だけを合成する。
- 空だけフィルム処理を除外する分岐も撤去した。空・雲・機体・地上・海面・HUDについて、既存の色調設定は変更していない。
- 積雲ターゲットは縦横1/3解像度を使用する。輪郭・機体との深度を考慮した4点補間は維持する。
- 積雲は120〜600mの区間の両端を台形積分し、直前の密度評価を次の区間へ再利用する。画面固定ディザや時間方向の履歴は使用しない。密度の細部LODは画素の投影幅から決める。
- 厚い雲の微細なセル状侵食を除き、大中の隆起を維持する。積雲の不透明度に応じてフィルム粒子を減衰させる。背景のフィルム粒子と色調は維持する。
- 低・中層の積雲は旧来の連続した3D密度場を維持する。以前の上層の積雲は薄雲へ置き換えた。
- 日照の端点補間、天候上限のキャッシュ、空白区間のスキップは維持する。密度0なら不要な積雲の積分・合成を行わない。
- 新しい画像・3Dテクスチャや履歴バッファは追加しない。

## 検証と計測

HLSLは`/Od /WX`・`/O3 /WX`で検証し、両方でフルHDの描画画像を取得する。
薄雲のみの設定、標準の少雲混合設定、密な積雲のストレス設定を確認する。

- 薄雲の表示、固定カメラ・時刻での完全一致、同一時刻の無風／有風の空の画素差による風の移動。元の色調を維持するため、雲を青寄りにする検査は行わない。
- 海面と手前のモデルの遮蔽、積雲内部の密度と微小移動、遠方での微小移動、最低品質での遠景。
- 透ける薄雲は、厚い雲の画面被覆検査で一様な曇天と扱わないようにし、強い画素差で厚い雲を検査する。
- 無効設定、密度0、負値・NaNなどの設定検証、および既存の戦闘・HUD・描画の回帰テスト。

`--clouds-review`は雲パスの8回平均に加え、薄雲を含む最終合成パスの時間も別に出力する。
薄雲の処理をPostへ移したため、Cloudsの時間だけで高速化を判断しない。
### 2026-11-08：旋回時の負荷変動の削減

- 天候セルを縦横8分割し、補間が単調であることを利用した保守的な上限で晴れ間をスキップする。密度が存在できない上端も厳密に除外する。
- 密度の端点を再利用する台形積分で、形状の計算を減らす。この計測時点では積雲は半解像度、筋雲はフル解像度。現在の1/3解像度化の計測は下記を参照。
- 太陽方向の積算は最大3点（遠景2点）。日照は距離1,200m間隔の固定節点で共有し、最初の密度検出位置に左右されない補間と同じ投影幅を使う。更新の境界で陰影の細かさが変わる縞を抑える。
- 2つの積雲帯の密度呼び出しを固定分岐にし、重み0のノイズ評価を省く。空の色、雲の生成高度、雲量、JSON・定数バッファは変更しない。
- 筋雲を含む`RetroFilmPS`も、`CloudPS`と同様にDebug／Releaseとも`/O3`で製品ビルドする。以下の比較は前後とも最適化シェーダーを使用し、このビルド設定変更の効果を加算しない。

RX 6600 XT、1920×1080、最適化シェーダー。実際の高高度設定で、固定位置・時刻のまま30度刻みの12方向を、高度1,500mと5,100mで比較した。各視点のCloudは8回描画平均、Postは同フレーム1回のGPU計測。以下は筋雲を含む **Cloud + Post** の時間。

| 視点 | 変更前 min / median / max | 変更後 min / median / max | 最大−最小 |
| --- | --- | --- | --- |
| 高度1,500m・12方向 | 6.11 / 6.93 / 8.44ms | 3.86 / 4.69 / 5.59ms | 2.33 → 1.73ms |
| 高度5,100m・12方向 | 6.84 / 8.16 / 12.36ms | 4.68 / 5.67 / 8.96ms | 5.52 → 4.28ms |

雲パス単体の最大値は7.83→4.98ms、11.84→8.44ms。これらはゲーム全体のFPSやフレーム時間p99ではなく、カメラ方向間の比較である。雲に近い重い方向では144FPSの時間予算（6.94ms）を超える負荷が残る。

同じシード・時刻の画像比較では、雲なし画像のRGB差は0。標準混合視点のRGB平均絶対差は0.736/255、99%点は11/255。重い旋回視点は平均1.636/255、密な雲内部は2.307/255。陰影の近似と積分方式を変更するため画素完全一致ではない。

`--clouds-review`は24視点の画像と個別時間、各高度のCloud+Postのmin/median/max/spreadを出力する。内部検証用の密な雲は従来の高度1,800〜10,500mを明示し、生成高度の変更で「雲の内部」テストが空を検査しないようにする。標準混合視点は現在の設定高度を使い、その見かけの被覆に合わせて上限を画面の35%とした。
Debug／Releaseビルド、最終シェーダーのコンパイル・GPU画像検証は成功した。混合設定追加後の全体回帰テストも成功している。
空の色を戻した後、以前の雲なし画像（1920×1080）と比較したところ、RGBAの8,294,400成分のうち1成分だけ1階調の差があり、残りは一致した。背景に意図的な色変更は加えていない。

## 1/3解像度での軽量化

ユーザーの解像度低下の許可を受け、厚い積雲のターゲットを縦横1/2から1/3へ変更した。フルHDでは960×540から640×360となり、画素数は518,400から230,400へ約55.6%減る。画面寸法が3の倍数でない場合は切り上げる。

筋雲は引き続きフル解像度で評価する。雲の生成高度、雲量、密度、色調、空の描画は変更しない。形状・自己陰影のシェーダーバイナリは比較前後で同一。新たなディザや時間方向の処理も追加しない。深度を考慮した4点拡大合成を維持するが、厚い雲の細部は1/2解像度より柔らかくなる。破棄を指定された入力ループ・表示待ち・Raw Inputメモリ再利用の処理は含めない。

2026-11-08、RX 6600 XT、1920×1080、同じシード・時刻・24視点で比較。Cloudは8回描画平均、Postは1回のGPU計測。カメラを固定した方向間の比較であり、ゲーム全体のFPSやフレーム時間p99ではない。

| 視点・12方向 | 雲のみ median / max（変更前→後） | 雲＋Post median / max（変更前→後） |
| --- | --- | --- |
| 高度1,500m | 4.42 / 5.07 → 2.59 / 3.06ms | 5.03 / 5.68 → 3.20 / 3.66ms |
| 高度5,100m | 5.57 / 8.63 → 2.78 / 4.06ms | 6.09 / 9.15 → 3.33 / 4.59ms |

標準混合視点は雲のみ3.50→2.38ms、Postは0.57→0.58ms。最大の雲＋Post時間は約50%減少した。Debug／Releaseビルド、HLSLの`/Od /WX`・`/O3 /WX`、全体回帰テストと最適化シェーダーのフルHD描画検査に成功した。固定条件の再現性、風、内部の微小移動、海面・モデルの深度遮蔽と1/3ターゲットの実寸を確認している。

### 2026-11-08：参考画像に合わせた形状と配置

航空ゲームの水平視点と、海上の積雲を上から見た参考画像に合わせ、縦に孤立した塊から横方向に連なる隆起へ変更した。
広域の天候ノイズで雲底をそろえ、雲量を0.24から0.34へ増やした。色調、フィルム処理、太陽・環境光の設定は変更していない。
追加画像や3Dテクスチャ、履歴バッファは使用しない。公開の設定形式・定数バッファの配置も維持する。

RX 6600 XT、1920×1080、最適化した雲シェーダーを使い、固定時刻・固定カメラで雲パスを1回ウォームアップ後、8回描画したGPUタイムスタンプの平均を取得した。
標準確認視点（位置0,1500,0／注視点0,3500,-8000）の雲パスは変更前1.50〜1.54ms、変更後1.97〜1.99ms。
最終ビルドでの再実行では同じ標準視点で2.05〜3.25msとなり、実行間のばらつきもある。
変更後は雲量・形状・陰影が異なるため、同じ雲の陰影計算だけを比較した値ではない。
発達した雲への中距離視点は約1.90ms、接近時は約7.83ms、内部は約8.31msだった。
雲パス単体の値であり、ゲーム全体の144FPS維持を保証する測定ではない。特に近距離・内部では負荷が増える。

通常の回帰テストは1000×600で実行する。フルHDの画像とGPU時間は、テスト実行ファイルにリポジトリ、出力フォルダー、`--clouds-review`を渡して取得する。
シード・太陽方向の変更、固定条件の再現性、風、上空／下／内部、海面・モデルによる遮蔽を検証する。
密度が存在する雲内部の視点では、画面の半分以上が雲の影響を受けることと、0.5m移動時の平均差が1階調未満であることも検証する。
レビュー用には合成前のRGBA16F密度積分結果も`clouds-density.dds`へ保存する。
